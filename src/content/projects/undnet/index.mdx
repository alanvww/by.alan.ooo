A collection of network forensics investigations, protocol architecture diagrams, and socket hardware/software experiments from Tom Igoe's **Understanding Networks** course at NYU ITP (Fall 2024). Across the semester, these labs traced how packets move from local interfaces and campus Wi-Fi resolvers out across submarine cables, autonomous systems, cloud firewalls, and custom TCP game servers.

## Lab 3 — Global Routing & `traceroute` Topology

To see how physical geography and autonomous system peering shape packet latency, I ran `traceroute` to `alan.ooo` (Cloudflare anycast `172.67.136.143`), `youtube.com`, `google.com`, `reddit.com`, and `torproject.org` from two vantage points:

1. **Local Residential Fiber (Verizon FiOS, NYC/NJ `98.109.25.1`)**: Reaches Cloudflare and Google edge nodes in **6–8 ms** within the New York metro area, or routes via Hurricane Electric (`he.net`) from NYC (`nyc4`) to Dallas (`dal1`/`dal2`) in **~43 ms** for `torproject.org`.
2. **VPN Exit Node in Hong Kong (`138.199.62.204`, Datacamp Limited / CDN77 HKG)**: Introduces a **~220–260 ms** trans-Pacific baseline, routing across Equinix Hong Kong (`15169.hkg.equinix.com`), NTT Global IP Network (`tokyjp10.jp.bb.gin.ntt.net`), Taipei, and Manila (`mnl07s01-in-f14.1e100.net`).

## Lab 4 — Face-Tracked OSC-to-TCP Controller for `BallDropServer`

For our networked multiplayer game assignment using Tom Igoe's TCP **`BallDropServer`** (where players connect over raw TCP sockets on port `8080` and send `w`, `a`, `s`, `d` ASCII commands to move their paddle), I built a custom **Node.js UDP-to-TCP bridge** (`OSCServer/server.js`).

An iPhone running ARKit face tracking streams real-time facial landmark coordinates over Wi-Fi via **OSC (Open Sound Control)** over UDP. The Node.js server listens on the local UDP port, thresholds head tilt/position into directional commands (`w`/`a`/`s`/`d`), and writes them directly to the persistent `net.Socket` TCP connection on `BallDropServer`.

## Lab 5 — Web Tracking Audits & DNS Packet Capture (`tcpdump`)

The final module examined application-layer tracking and DNS transport privacy on the NYU campus network (`10.18.207.216`).

### Browser Fingerprinting & Blacklight Audits

Testing browser configurations against the EFF's **Cover Your Tracks** tool demonstrated the shift from standard ad/tracker blocking (which still left a unique browser fingerprint) to randomized fingerprint protection. Running The Markup's **Blacklight** inspector across four domains highlighted the contrast between static/privacy-first sites (`www.alan.ooo` and `ml5js.org` with **0 trackers / 0 third-party cookies**), `by.alan.ooo`, and institutional portals (`itp.nyu.edu/itp/` with **4 ad trackers and 5 third-party cookies**).

### Live Port 53 Inspection with `tcpdump`

Capturing live port `53` traffic on `en0` (`sudo tcpdump -i en0 -s0 port 53`) and the Tailscale tunnel interface `utun0` (`sudo tcpdump -i utun0 -s0 port 53`) exposed every plaintext `A`, `AAAA`, `CNAME`, `PTR`, and `Type65` (HTTPS) DNS query leaving the machine—and demonstrated how routing through **Tailscale MagicDNS** (`100.100.100.100`) and **NextDNS** changes resolver visibility.
